L'assistance par Intelligence Artificielle pour les développeurs a franchi trois étapes décisives en moins de cinq ans :
1. **L'autocomplétion de code** (GitHub Copilot) : prédiction de la ligne suivante au sein de l'éditeur.
2. **Le chat interactif** (ChatGPT, Claude) : échange conversationnel nécessitant de copier-coller manuellement le code et les erreurs.
3. **L'ère des Agents Autonomes** (**Claude Code**, Antigravity, Cursor) : des systèmes capables d'inspecter un dépôt Git, d'exécuter des commandes de terminal, d'analyser les traces de bugs, de modifier des dizaines de fichiers de façon coordonnée et de s'auto-corriger.

Dans ce dossier technique, nous explorons l'architecture interne de **Claude Code** (le CLI agence d'Anthropic) et nous disséquons le standard ouvert qui est en train d'unifier l'écosystème : le **Model Context Protocol (MCP)**.

## 1. Comment Fonctionne Claude Code : La Boucle ReAct

Contrairement à un simple plugin IDE qui ne "voit" que le fichier actif dans l'éditeur, Claude Code opère directement dans le shell de votre machine selon une boucle agentique **ReAct** (*Reasoning + Acting*) :

```txt
                              [ Objectif du Dev ]
                                       │
                                       ▼
                       ┌──────────────────────────────┐
                       │      1. PENSÉE (Reasoning)   │
                       │ Analyse du contexte & plan   │
                       └───────────────┬──────────────┘
                                       │
                                       ▼
                       ┌──────────────────────────────┐
                       │       2. ACTION (Acting)     │
                       │ Appel d'outil (Read/Edit/Run)│
                       └───────────────┬──────────────┘
                                       │
                                       ▼
                       ┌──────────────────────────────┐
                       │     3. OBSERVATION (Obs)     │
                       │ Sortie terminal, logs d'erreur│
                       └───────────────┬──────────────┘
                                       │
                         Succès ? ─────┴───── Non (Auto-correction)
                            │                       │
                           OUI                      └──────┐
                            ▼                              │
                   [ Commit & PR Git ]                     ▼
                                            (Nouvelle Pensée corrective)
```

### Les 4 Outils Fondamentaux du CLI
Pour interagir avec votre machine en toute sécurité, l'agent dispose de primitives standardisées :
- **Glob / Grep / Read** : Découverte sémantique de l'arborescence et lecture ciblée des tranches de code sans saturer la fenêtre de contexte.
- **File Edit** : Modifications atomiques sous forme de diffs précis pour préserver les commentaires et le style existant.
- **Bash Execution** : Exécution de tests (`npm test`), linters (`eslint`) et vérifications de types (`tsc`).
- **Git Integration** : Création automatique de branches temporaires (*worktrees*) et commits atomiques conventionnels.

```bash
# Exemple de commande en langage naturel déléguée à l'agent
$ claude "Migre la table User vers le nouveau schéma Prisma et adapte tous les tests unitaires cassés"
```

## 2. Le Standard MCP (Model Context Protocol)

Avant le MCP, chaque outil d'IA devait créer ses propres connecteurs propriétaires pour accéder à une base PostgreSQL, un dépôt GitHub ou un bucket AWS.

Créé par Anthropic et publié en open source, le **Model Context Protocol (MCP)** est à l'IA ce que **LSP (Language Server Protocol)** a été aux éditeurs de code : un standard de communication universel fondé sur **JSON-RPC 2.0**.

```txt
┌─────────────────────────────────────────────────────────────┐
│                       Client MCP (Hôte)                     │
│         (Claude Code, Claude Desktop, Antigravity IDE)      │
└──────────────────────────────┬──────────────────────────────┘
                               │ JSON-RPC 2.0 (stdio ou SSE)
        ┌──────────────────────┼──────────────────────┐
        ▼                      ▼                      ▼
┌──────────────┐       ┌──────────────┐       ┌──────────────┐
│ Serveur MCP  │       │ Serveur MCP  │       │ Serveur MCP  │
│   Postgres   │       │    GitHub    │       │ Documentation│
│ (Tables/SQL) │       │ (PRs/Issues) │       │  Interne     │
└──────────────┘       └──────────────┘       └──────────────┘
```

Le protocole expose 3 primitives fondamentales :
1. **Tools (Outils)** : Fonctions exécutables par le LLM (ex: `execute_sql_query`, `deploy_service`).
2. **Resources (Ressources)** : Données passives en lecture seule (ex: schémas de base de données, fichiers de logs).
3. **Prompts** : Modèles d'invites pré-paramétrés pour guider le modèle sur des tâches récurrentes.

## 3. Construire un Serveur MCP Personnalisé en TypeScript

Pour comprendre la puissance du MCP, créons un serveur MCP personnalisé qui permet à Claude Code de surveiller les métriques système (mémoire vive et espace disque) d'un serveur de production :

```typescript
// server-mcp-systeme.ts
import { Server } from '@modelcontextprotocol/sdk/server/index.js';
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js';
import {
  CallToolRequestSchema,
  ListToolsRequestSchema,
} from '@modelcontextprotocol/sdk/types.js';
import * as os from 'os';

// 1. Initialisation de l'instance serveur MCP
const server = new Server(
  { name: 'serveur-metriques-systeme', version: '1.0.0' },
  { capabilities: { tools: {} } }
);

// 2. Déclaration de l'outil exposé au modèle de langage
server.setRequestHandler(ListToolsRequestSchema, async () => {
  return {
    tools: [
      {
        name: 'obtenir_statistiques_memoire',
        description: 'Renvoie la mémoire vive totale, libre et le pourcentage d\'utilisation du serveur.',
        inputSchema: {
          type: 'object',
          properties: {},
        },
      },
    ],
  };
});

// 3. Implémentation de la logique d'exécution de l'outil
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  if (request.params.name === 'obtenir_statistiques_memoire') {
    const totalMem = os.totalmem();
    const freeMem = os.freemem();
    const usedMem = totalMem - freeMem;
    const usagePercent = ((usedMem / totalMem) * 100).toFixed(2);

    return {
      content: [
        {
          type: 'text',
          text: JSON.stringify(
            {
              totalMo: Math.round(totalMem / 1024 / 1024),
              libreMo: Math.round(freeMem / 1024 / 1024),
              utiliseMo: Math.round(usedMem / 1024 / 1024),
              pourcentageUtilise: `${usagePercent}%`,
            },
            null,
            2
          ),
        },
      ],
    };
  }

  throw new Error(`Outil inconnu : ${request.params.name}`);
});

// 4. Lancement du serveur sur l'entrée/sortie standard (stdio)
async function main() {
  const transport = new StdioServerTransport();
  await server.connect(transport);
  console.error('Serveur MCP de métriques système démarré sur stdio.');
}

main().catch(console.error);
```

### Configuration dans l'environnement
Pour connecter ce serveur à votre agent, il suffit de l'ajouter dans votre fichier de configuration JSON (par exemple `claude_desktop_config.json` ou `.mcp.json`) :

```json
{
  "mcpServers": {
    "system-monitor": {
      "command": "npx",
      "args": ["tsx", "/chemin/vers/server-mcp-systeme.ts"]
    }
  }
}
```

Dès cet instant, l'agent peut appeler nativement l'outil `obtenir_statistiques_memoire` pour diagnostiquer un incident en direct sans qu'aucun prompt spécifique ne soit nécessaire !

## 4. Bonnes Pratiques pour Collaborer avec un Agent Développeur

Travailler efficacement avec des agents autonomes nécessite une nouvelle discipline d'ingénierie :

| Pratique | Pourquoi c'est crucial ? |
| :--- | :--- |
| **Avoir une suite de tests automatisée rapide** | L'agent s'auto-corrige en s'appuyant sur vos tests (`npm test`). Sans tests fiables, l'agent ne peut pas valider qu'il n'a rien cassé. |
| **Typage strict TypeScript (`strict: true`)** | Le compilateur `tsc` sert de garde-fou immédiat : l'agent répare ses propres erreurs de typage avant de vous solliciter. |
| **Demandes atomiques et ciblées** | Demandez une tâche précise à la fois plutôt que "Refais toute l'architecture de l'app". |
| **Revue de diff systématique** | L'agent propose, l'ingénieur dispose. Inspectez toujours les `git diff` avant de fusionner. |

<Note>
**Sécurité en environnement sensible** : Configurez toujours votre CLI pour exiger une confirmation humaine explicite avant toute action destructive (suppression de fichiers, commandes `DROP TABLE`, déploiements en production).
</Note>

## Conclusion

L'association d'outils CLI agentiques comme **Claude Code** et du standard ouvert **MCP** marque le passage de l'IA comme simple générateur de texte à l'IA comme collaborateur technique opérationnel. L'ingénieur logiciel ne disparaît pas : son rôle évolue d'artisan tapant chaque caractère vers celui d'architecte, de chef d'orchestre et de relecteur critique.
