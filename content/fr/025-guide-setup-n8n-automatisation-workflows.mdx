# Guide Complet n8n : Setup Docker, Webhooks et Meilleures Pratiques d'Automatisation

Dans le paysage des outils d'automatisation no-code et low-code, **n8n** s'est imposé comme l'alternative open-source et auto-hébergeable la plus puissante face aux solutions propriétaires comme Zapier ou Make.

Grâce à son modèle de licence *fair-code*, vous pouvez héberger n8n sur vos propres serveurs sans payer de frais exorbitants par tâche exécutée, tout en gardant un contrôle absolu sur la confidentialité de vos données.

Dans cet article pratique, nous allons voir comment déployer n8n avec **Docker Compose**, comprendre les concepts fondamentaux (Triggers, Nodes, JSON) et appliquer les meilleures pratiques pour concevoir des workflows industriels résilients.

## 2. Déploiement de n8n avec Docker Compose

Pour un déploiement de production fiable avec base de données **PostgreSQL** et persistance des volumes :

```yaml
# docker-compose.yml
services:
  postgres:
    image: postgres:16-alpine
    restart: always
    environment:
      POSTGRES_USER: n8n_user
      POSTGRES_PASSWORD: secret_password_123
      POSTGRES_DB: n8n_db
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n_user -d n8n_db"]
      interval: 5s
      timeout: 5s
      retries: 5

  n8n:
    image: docker.n8n.io/n8nio/n8n:latest
    restart: always
    ports:
      - "5678:5678"
    environment:
      - DB_TYPE=postgresdb
      - DB_POSTGRESDB_HOST=postgres
      - DB_POSTGRESDB_PORT=5432
      - DB_POSTGRESDB_DATABASE=n8n_db
      - DB_POSTGRESDB_USER=n8n_user
      - DB_POSTGRESDB_PASSWORD=secret_password_123
      - N8N_HOST=n8n.votredomaine.com
      - N8N_PROTOCOL=https
      - WEBHOOK_URL=https://n8n.votredomaine.com/
      - GENERIC_TIMEZONE=Europe/Paris
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

volumes:
  postgres_data:
  n8n_data:
```

### Lancement du service :

```bash
docker compose up -d
```

En quelques secondes, l'interface web de n8n est accessible sur le port `5678` (ou derrière un reverse proxy Traefik / Caddy / Dokploy avec SSL automatique).

## 3. Les Piliers Conceptuels de n8n

Pour maîtriser n8n, il est essentiel de comprendre comment circule l'information à travers un workflow :

```txt
┌──────────────┐       ┌──────────────┐       ┌──────────────┐
│   TRIGGER    │ ────► │  TRANSFORM   │ ────► │    ACTION    │
│  (Webhook,   │       │ (Code JS,    │       │(Slack, Email,│
│   Cron, etc.)│       │  Filtre, Set)│       │ Postgres DB) │
└──────────────┘       └──────────────┘       └──────────────┘
```

1. **Les Triggers (Déclencheurs)** :
   - **Webhook** : Écoute les requêtes HTTP POST entrantes (ex: formulaire de contact, événement Stripe, webhook GitHub).
   - **Schedule (Cron)** : Exécute le workflow selon une fréquence horaire ou calendaire définie.
   - **Polling Trigger** : Interroge régulièrement une API (ex: nouveau message Discord, nouvel email Gmail).

2. **La structure des données (Tableau d'objets JSON)** :
   - Dans n8n, toute donnée circule obligatoirement sous forme d'un tableau d'objets JSON :
     `[{ json: { id: 1, name: "Alice" } }, { json: { id: 2, name: "Bob" } }]`.
   - Chaque nœud en aval traite automatiquement chaque élément de ce tableau, ce qui simplifie le traitement par lots sans écrire de boucles manuelles.

3. **Le nœud Code (JavaScript / Python)** :
   - Lorsque les nœuds standards ne suffisent pas, le nœud **Code** permet de manipuler les données avec du JavaScript pur :

```javascript
// Nœud Code dans n8n
return $input.all().map(item => {
  return {
    json: {
      fullName: `${item.json.firstName} ${item.json.lastName}`.toUpperCase(),
      createdAt: new Date().toISOString(),
      isValid: item.json.email.includes('@')
    }
  };
});
```

## 4. Les Bonnes Pratiques pour des Automatisations Indestructibles

### 1. La gestion des erreurs (Error Trigger Workflow)
Ne laissez jamais un workflow échouer silencieusement. Dans les paramètres de n8n (`Workflow Settings`), vous pouvez assigner un **Error Workflow dédié**. Si une étape plante (ex: API externe indisponible), le workflow d'erreur est automatiquement déclenché pour vous alerter sur Slack ou par email avec la trace exacte du problème.

### 2. Le chiffrement des identifiants (Encryption Key)
Définissez toujours une clé secrète fixe via la variable d'environnement `N8N_ENCRYPTION_KEY`. Si vous devez migrer votre base de données sur un nouveau serveur, cette clé vous permettra de restaurer vos identifiants d'API chiffrés sans avoir à tout reconfigurer.

### 3. Sauvegarde et Versioning (Git Integration)
Exportez régulièrement vos workflows sous forme de fichiers JSON ou utilisez le nœud n8n Git pour synchroniser vos automatisations dans un dépôt GitHub privé.
