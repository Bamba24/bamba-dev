# Sous le Capot des LLMs : Tokens, Fenêtre de Contexte, Traitement des Requêtes et Modèles de Coûts

L'intelligence artificielle générative et les modèles de langage (LLMs) ont bouleversé le développement logiciel. Pourtant, pour une grande majorité de développeurs, un LLM reste une boîte noire magique : on envoie une chaîne de caractères en entrée, on attend un peu, et une réponse textuelle apparaît.

Mais dès que l'on déploie une fonctionnalité d'IA en production, les réalités techniques et financières s'imposent :
- *Pourquoi ma facture d'API explose-t-elle à la fin du mois ?*
- *Pourquoi la génération de texte est-elle progressive alors que le prompt d'entrée est lu instantanément ?*
- *Pourquoi les tokens de sortie coûtent-ils 3 à 5 fois plus cher que les tokens d'entrée ?*

Dans ce guide d'ingénierie, nous allons ouvrir le capot des Transformers pour comprendre **ce qu'est un token**, comment une requête voyage de l'entrée à la sortie, comment fonctionne la **fenêtre de contexte**, et comment maîtriser les **coûts de vos modèles d'IA**.

---

## 1. Qu'est-ce qu'un Token ? La Monnaie Élémentaire des LLMs 🪙

Contrairement aux humains, **un modèle de langage ne lit ni les lettres de l'alphabet, ni les mots complets**. Il ne manipule que des suites de nombres entiers appelés **Tokens**.

### Le Découpage par Byte-Pair Encoding (BPE)

Les modèles modernes (GPT-4o, Claude 3.5, Gemini 2.0, Llama 3) utilisent des algorithmes de tokenization comme le **Byte-Pair Encoding (BPE)** ou **SentencePiece** :

1. Les mots fréquents de la langue anglaise forment souvent un seul token : `"developer"` ➔ 1 token.
2. Les mots rares ou longs sont fractionnés en plusieurs sous-mots : `"anticonstitutionnellement"` ➔ 6 tokens (`["anti", "constit", "ution", "nelle", "ment"]`).
3. Les espaces, sauts de ligne et symboles de ponctuation comptent comme des tokens à part entière (un espace devant un mot change son ID numérique).
4. En code informatique, une indentation de 4 espaces ou un crochet `{` est un token.

```txt
Texte brut : "L'intelligence artificielle transforme le code."
              │
              ▼ Algorithme de Tokenization (Vocabulaire de ~128 000 tokens)
Tokens découpés : ["L'", "intelligence", " artificielle", " transforme", " le", " code", "."]
              │
              ▼ Encodage numérique
IDs entiers :     [452,     19842,           32891,           11204,       481,   2910,   13]
```

<Note>
**L'impact de la langue sur la facture :**
Les algorithmes de tokenization sont majoritairement entraînés sur des corpus anglophones. En anglais, **1 mot correspond à environ 1,3 token**. En français, à cause des accents et des élisions (`l'`, `d'`), **1 mot équivaut souvent à 1,5 à 1,8 token**. Pour un même contenu, une requête en français consomme environ 25% à 40% de tokens de plus qu'en anglais !
</Note>

## 2. Le Voyage d'une Requête : De l'Entrée à la Sortie 🔄

Comment un modèle transforme-t-il votre prompt en une réponse cohérente ? Ce processus se déroule en 4 étapes majeures :

```txt
[ 1. PROMPT UTILISATEUR ]
          │
          ▼ (Tokenization BPE)
[ 2. SUITE D'IDENTIFIANTS NUMÉRIQUES ]
          │
          ▼ (Projection vectorielle / Embeddings)
[ 3. ESPACE GÉOMÉTRIQUE VECTORIEL (d = 4096 dimensions) ]
          │
          ▼ (Couches d'Attention Multi-Têtes / Transformers)
[ 4. DISTRIBUTION SOFTMAX SUR 128 000 TOKENS ]
          │
          ▼ (Sélection du token suivant : "Next Token Prediction")
[ 5. ÉMISSION D'UN SEUL TOKEN ] ──► Réinjecté en entrée pour le token suivant !
```

### Étape A : L'Ingestion Parallèle du Prompt (Entrée)

Lorsque vous envoyez un texte de 2 000 tokens au modèle :
1. Le prompt complet est transformé en vecteurs d'embeddings.
2. Grâce aux puces GPU (Nvidia H100 / TPU Google), **tous les tokens du prompt sont analysés simultanément en parallèle**.
3. Le mécanisme d'**Attention (Multi-Head Self-Attention)** calcule la relation mathématique entre chaque mot du texte (par exemple : le pronom *"il"* se réfère au mot *"serveur"* apparu 3 phrases plus tôt).

Cette étape est extrêmement rapide car elle exploite la parallélisation massive des cartes graphiques.

### Étape B : La Génération Auto-Régressive (Sortie)

Contrairement à l'entrée, **la réponse ne peut PAS être générée en un seul bloc**.

Un LLM fonctionne en **auto-régression séquentielle** :
1. Il prédit le **premier mot** de sa réponse.
2. Il prend ce mot, l'ajoute à la fin de la conversation.
3. Il recalcule tout pour prédire le **deuxième mot**.
4. Il répète cette boucle jusqu'à prédire le token spécial de fin : `<|end_of_text|>`.

```txt
Boucle de génération :
Prompt initial                   ➔ Prédit : "Le"
Prompt + "Le"                    ➔ Prédit : "système"
Prompt + "Le système"            ➔ Prédit : "est"
Prompt + "Le système est"        ➔ Prédit : "opérationnel"
Prompt + ... + "opérationnel"    ➔ Prédit : <FIN>
```

C'est exactement pour cette raison que les tokens de sortie s'affichent un par un à l'écran via le protocole **Streaming (Server-Sent Events / SSE)** !

### Température & Échantillonnage (Sampling)

À chaque étape, le modèle génère une liste de probabilités pour chacun des 128 000 tokens du vocabulaire. Comment choisit-il le gagnant ?

- **Température = 0 (Déterministe)** : Le modèle choisit toujours le token ayant la plus haute probabilité mathématique (idéal pour le code SQL, JSON ou les calculs).
- **Température = 0.7 à 1.0 (Créative)** : Le modèle tire au sort parmi les meilleurs choix possibles, produisant un texte plus varié et inventif.
- **Top-P (Nucleus Sampling)** : Restreint la sélection aux tokens dont la somme des probabilités atteint un seuil P (ex: 90%), éliminant les mots aberrants.

## 3. La Fenêtre de Contexte & La Révolution du Prompt Caching 🧠

La **fenêtre de contexte** représente la quantité maximale de tokens (prompt + historique + réponse) que le modèle peut garder en mémoire de travail à un instant T.

### L'Évolution Vertigineuse des Contextes

| Modèle | Année | Taille de Contexte | Équivalent Livre |
| :--- | :--- | :--- | :--- |
| **GPT-3** | 2020 | 2 048 tokens | ~4 pages |
| **GPT-3.5-Turbo** | 2023 | 4 096 à 16 000 tokens | ~30 pages |
| **GPT-4o / Claude 3.5 Sonnet**| 2024 | 128 000 à 200 000 tokens | ~400 pages (Un roman) |
| **Gemini 1.5 Pro / 2.0 Flash** | 2025 | 1 000 000 à 2 000 000 tokens | ~1 heure de vidéo ou 50 000 lignes de code |

### Le Piège du "Lost in the Middle"

Même si un modèle supporte 200 000 tokens, les Transformers souffrent du phénomène d'**attention en U** :
- Le modèle retient parfaitement les consignes situées **au tout début du prompt** (le *System Prompt*).
- Il retient très bien les derniers échanges situés **à la toute fin du prompt**.
- En revanche, sa capacité d'attention a tendance à faiblir sur les informations perdues **au milieu** d'un document géant de 100 000 tokens.

### Le Sauveur Financier : Le Prompt Caching (KV-Cache)

Auparavant, si vous utilisiez un agent de code avec 50 000 tokens de contexte de projet, vous payiez l'analyse de ces 50 000 tokens **à chaque message**.

Les fournisseurs modernes (Anthropic, OpenAI, DeepSeek, Google) ont introduit le **Prompt Caching** :
- Le calcul de l'attention sur la partie statique du prompt est **conservé en mémoire RAM GPU** pendant quelques minutes.
- Lorsque vous posez une nouvelle question avec le même préfixe, le modèle réutilise directement ce cache sans recalculer les vecteurs.
- **Résultat** : Une réduction de **50% à 90% du coût** des tokens d'entrée et une latence de premier token divisée par 4 !

## 4. Panorama des Modèles d'IA & Économie des Coûts (Tokenomics) 💰

Pourquoi le modèle de facturation des APIs d'IA distingue-t-il systématiquement le prix d'entrée du prix de sortie ?

```txt
┌────────────────────────────────────────────────────────┐
│           POURQUOI LA SORTIE COÛTE PLUS CHER ?         │
├────────────────────────────────────────────────────────┤
│ • Tokens d'Entrée : Traités en parallèle sur les GPUs. │
│   Le matériel est optimisé à 100%.                     │
│                                                        │
│ • Tokens de Sortie : Traités de manière séquentielle   │
│   (1 token après l'autre). Le GPU doit attendre le     │
│   résultat précédent pour chaque mot généré.           │
│                                                        │
│ 👉 CONSÉQUENCE : Un token de sortie coûte généralement │
│   3 à 5 fois plus cher qu'un token d'entrée !          │
└────────────────────────────────────────────────────────┘
```

### Comparatif des Grandes Familles de Modèles (Prix indicatifs par Million de Tokens)

| Catégorie | Modèles de référence | Prix Entrée / 1M | Prix Sortie / 1M | Cas d'usage idéal |
| :--- | :--- | :--- | :--- | :--- |
| **Ultra-Rapides & Légers** | GPT-4o-mini, Claude 3.5 Haiku, Gemini 2.0 Flash | ~0,075 $ à 0,80 $ | ~0,30 $ à 4,00 $ | Tri d'emails, chatbots simples, extraction JSON, classification |
| **Polyvalents Haut de Gamme** | Claude 3.5 Sonnet, GPT-4o | ~3,00 $ | ~15,00 $ | Codage complexe, analyse d'architecture, rédaction créative |
| **Modèles de Raisonnement (CoT)**| OpenAI o1, o3-mini, DeepSeek R1, Gemini Thinking | ~1,10 $ à 15,00 $ | ~4,40 $ à 60,00 $ | Mathématiques, sécurité, algorithmique difficile, débogage complexe |

### Le Coût Caché des "Reasoning Tokens" (Tokens de Pensée)

Les nouveaux modèles comme **o1**, **o3-mini** ou **DeepSeek R1** intègrent une chaîne de pensée interne (*Chain of Thought*) avant de répondre.

Lorsque vous demandez : *« Résous ce problème algorithmique »*, le modèle peut générer intérieurement **4 000 tokens de réflexion** qu'il ne vous affiche pas dans sa réponse finale.
Pourtant, **ces tokens de réflexion vous sont facturés au prix fort des tokens de sortie** ! Une requête en apparence courte peut ainsi coûter dix fois plus cher que prévu si le modèle réfléchit longuement.

## 5. Stratégies d'Optimisation des Coûts en Production

Pour éviter que votre facture cloud n'explose, appliquez ces règles de conception logicielle :

1. **Le Model Routing (Aiguillage Intelligent)** :
   Ne routez pas 100% du trafic vers Claude 3.5 Sonnet ou GPT-4o. Utilisez un petit modèle (Gemini Flash ou GPT-4o-mini) pour qualifier la question de l'utilisateur, et n'appelez le grand modèle que si la complexité de la tâche l'exige.
2. **Troncature d'Historique de Conversation** :
   Dans un chat multi-tours, ne renvoyez pas l'intégralité des 50 messages précédents. Conservez uniquement les 6 derniers échanges et résumez les échanges plus anciens.
3. **Exploiter le Prompt Caching** :
   Placez vos consignes statiques (*System Prompts* volumineux, schémas de base de données, documentation d'API) tout au début du prompt pour maximiser le taux de cache hit.
4. **Sortie JSON Stricte avec `max_tokens`** :
   Définissez systématiquement une limite `max_tokens` adaptée. Si vous n'attendez qu'un booléen ou un ID, bloquez la sortie à 50 tokens pour éviter qu'un modèle bavard ne consomme 500 tokens inutiles.

## Conclusion

Dans l'écosystème de l'intelligence artificielle moderne, le code ne se contente plus de manipuler de la mémoire RAM et des disques durs : il orchestre des flux de tokens et des fenêtres d'attention sur des clusters de calcul distribués.

Maîtriser la tokenization, la nature séquentielle de la génération et l'architecture des coûts permet aux développeurs de transformer des prototypes impressionnants en véritables produits d'entreprise rentables et pérennes.
