# Authentification et Gestion de Rôles avec Better Auth dans Next.js

Dans l'univers Next.js et TypeScript, la mise en place d'un système d'authentification robuste a longtemps été une source de maux de tête. Entre les changements d'API incessants de NextAuth/Auth.js et la complexité des configurations de sessions en App Router, beaucoup de développeurs peinaient à obtenir un système à la fois simple, sécurisé et strictement typé.

C'est dans ce contexte que **Better Auth** a émergé comme une véritable révolution : une bibliothèque d'authentification TypeScript-first complète, modulaire et compatible nativement avec tous les ORMs modernes (Prisma, Drizzle, Kysely).

Dans cet article, nous allons mettre en place une authentification complète dans Next.js App Router avec un système de **contrôle d'accès basé sur les rôles (RBAC : Admin, Modérateur, Utilisateur)**.

---

## 1. Pourquoi Better Auth ?

| Fonctionnalité | NextAuth / Auth.js | Better Auth |
| :--- | :--- | :--- |
| **Typage TypeScript** | Complexe, nécessite de surcharger les modules (`declare module`) | Inférence automatique de bout en bout |
| **Gestion des Rôles (RBAC)** | Manuelle (callbacks JWT & session) | Plugin officiel `admin` natif prêt à l'emploi |
| **Compatibilité ORM** | Adaptateurs parfois obsolètes | Schémas automatiques Prisma / Drizzle |
| **Gestion des Sessions** | Stateless JWT ou base | Hybride ultra-sécurisé avec cookies HttpOnly |

## 2. Installation et Configuration du Serveur

Installez Better Auth et le client correspondant :

```bash
npm install better-auth
```

### Initialisation du serveur d'authentification (`lib/auth.ts`) :

```typescript
// lib/auth.ts
import { betterAuth } from "better-auth";
import { prismaAdapter } from "better-auth/adapters/prisma";
import { admin } from "better-auth/plugins";
import { prisma } from "@/lib/prisma";

export const auth = betterAuth({
  database: prismaAdapter(prisma, {
    provider: "postgresql",
  }),
  emailAndPassword: {
    enabled: true,
  },
  plugins: [
    // Active la gestion des rôles : 'admin', 'user', ou rôles personnalisés
    admin({
      defaultRole: "user",
      adminRoles: ["admin", "superadmin"],
    }),
  ],
});
```

## 3. Schéma de Base de Données (Prisma)

Better Auth fournit un modèle de base clair pour vos tables d'utilisateurs, sessions et rôles :

```prisma
// prisma/schema.prisma
model User {
  id            String    @id @default(uuid())
  name          String
  email         String    @unique
  emailVerified Boolean   @default(false)
  image         String?
  role          String    @default("user") // 'admin' | 'user' | 'moderator'
  banned        Boolean?  @default(false)
  createdAt     DateTime  @default(now())
  updatedAt     DateTime  @updatedAt
  sessions      Session[]
  accounts      Account[]
}

model Session {
  id        String   @id @default(uuid())
  userId    String
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  token     String   @unique
  expiresAt DateTime
  ipAddress String?
  userAgent String?
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}

model Account {
  id                    String    @id @default(uuid())
  userId                String
  user                  User      @relation(fields: [userId], references: [id], onDelete: Cascade)
  accountId             String
  providerId            String
  accessToken           String?
  refreshToken          String?
  accessTokenExpiresAt DateTime?
  password              String?
  createdAt             DateTime  @default(now())
  updatedAt             DateTime  @updatedAt
}
```

## 4. Route Handler Next.js App Router

Créez le point d'entrée API unique qui traite toutes les requêtes d'authentification (`/api/auth/*`) :

```typescript
// app/api/auth/[...all]/route.ts
import { auth } from "@/lib/auth";
import { toNextJsHandler } from "better-auth/next-js";

export const { GET, POST } = toNextJsHandler(auth);
```

## 5. Le Client d'Authentification (`lib/auth-client.ts`)

Pour interagir avec le système dans vos composants React côté client :

```typescript
// lib/auth-client.ts
import { createAuthClient } from "better-auth/react";
import { adminClient } from "better-auth/client/plugins";

export const authClient = createAuthClient({
  baseURL: process.env.NEXT_PUBLIC_APP_URL || "http://localhost:3000",
  plugins: [adminClient()],
});

export const { signIn, signUp, signOut, useSession } = authClient;
```

## 6. Protection des Vues et Gestion des Rôles

### Côté Client : Affichage conditionnel selon le rôle

```tsx
"use client";

import { useSession, signOut } from "@/lib/auth-client";

export function UserNav() {
  const { data: session, isPending } = useSession();

  if (isPending) return <div>Chargement...</div>;
  if (!session) return <a href="/login">Se connecter</a>;

  return (
    <div className="flex items-center gap-4">
      <span>{session.user.name} ({session.user.role})</span>
      
      {/* Accès restreint réservé aux administrateurs */}
      {session.user.role === "admin" && (
        <a href="/admin" className="text-amber-500 font-semibold">
          Panneau d'Administration
        </a>
      )}

      <button onClick={() => signOut()}>Déconnexion</button>
    </div>
  );
}
```

### Côté Serveur : Garde stricte dans un Server Component

Pour les pages sensibles (ex: `/admin`), la vérification doit impérativement s'effectuer côté serveur avec `auth.api.getSession` :

```typescript
// app/admin/page.tsx
import { auth } from "@/lib/auth";
import { headers } from "next/headers";
import { redirect } from "next/navigation";

export default async function AdminPage() {
  const session = await auth.api.getSession({
    headers: await headers(),
  });

  // 1. Vérification de l'authentification
  if (!session) {
    redirect("/login");
  }

  // 2. Vérification du rôle RBAC
  if (session.user.role !== "admin") {
    redirect("/unauthorized");
  }

  return (
    <main className="p-8">
      <h1 className="text-2xl font-bold">Espace Administrateur Sécurisé</h1>
      <p>Bienvenue {session.user.name}. Vous avez les droits complets.</p>
    </main>
  );
}
```

## Conclusion

En associant la puissance de Next.js App Router à **Better Auth**, vous bénéficiez d'une solution d'authentification moderne :
- **Zéro friction** : Un code concis et lisible.
- **Sécurité maximale** : Cookies HttpOnly signés et vérifications côté serveur.
