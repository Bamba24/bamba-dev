# Vibe Coding vs Dev Agentique : Révolution du Code par l'IA

« *Je ne lis même plus le code généré. Je parle à l'IA, je clique sur Accepter, je regarde si ça s'affiche dans le navigateur, et si ça marche, je vibre avec.* »

Cette déclaration d'Andrej Karpathy (fondateur d'OpenAI et ex-directeur de l'IA chez Tesla) début 2025 a formalisé un nouveau phénomène : le **Vibe Coding**. En déléguant aveuglément l'écriture du code aux modèles de langage (LLM), n'importe qui peut désormais donner naissance à un prototype fonctionnel en quelques heures.

Mais transposer cette pratique décontractée au sein d'une entreprise ou d'un système bancaire mène tout droit au désastre : dette technique ingérable, régressions invisibles, trous de sécurité béants et code spaghetti que personne n'est capable de maintenir.

À l'opposé du simple Vibe Coding se dresse le **Développement Agentique (*Agentic Software Engineering*)** : une discipline d'ingénierie rigoureuse où des agents autonomes opèrent sous le contrôle d'architectures strictes, de harnais de tests automatisés et de protocoles outillés (comme le MCP).

Dans ce guide d'analyse logicielle, nous confrontons ces deux visions et démontrons comment passer du bricolage expérimental à l'ingénierie de production assistée par agents.

## 1. Qu'est-ce que le Vibe Coding ?

Le **Vibe Coding** est une posture de développement où l'ingénieur abandonne délibérément la compréhension microscopique de la syntaxe pour se concentrer uniquement sur le flux créatif global :

- **Le workflow** : Vous décrivez votre idée en langage naturel dans un outil comme Cursor, Windsurf ou ChatGPT, l'IA génère 400 lignes de JavaScript, vous rechargez la page, constatez le résultat visuel et continuez d'avancer au feeling.
- **Ses forces indéniables** : Une vélocité d'exploration inégalée pour créer un Minimum Viable Product (MVP), concevoir une landing page ou prototyper une interface lors d'un hackathon le week-end.
- **Ses limites mortelles en production** :
  - **L'illusion de la compétence** : Tant que le code marche en surface, tout semble parfait. Mais dès qu'un cas limite (*edge case*) survient, personne dans l'équipe ne sait comment le code fonctionne en profondeur.
  - **La dette de sécurité** : L'IA injecte fréquemment des dépendances obsolètes, des requêtes SQL non paramétrées ou des fuites de mémoire invisibles à l'œil nu.

### L'Analogie du Monde Réel
> **L'Analogie du Menuisier du Dimanche vs L'Architecte de Gratte-Ciel :** Le Vibe Coding est comme fabriquer une cabane de jardin avec des palettes et une boîte de clous : en une après-midi, vous avez un abri qui tient debout et fait le job. Le Développement Agentique est l'édification d'une tour résidentielle de 50 étages : vous utilisez des grues robotisées et des pelleteuses autonomes haute technologie, mais chaque poutre en acier respecte scrupuleusement les calculs de résistance des matériaux du bureau d'études.

## 2. Qu'est-ce que le Développement Agentique ?

Le **Développement Agentique** ne se débarrasse pas des règles de l'ingénierie logicielle : il les renforce pour guider l'intelligence artificielle.

Dans ce paradigme, l'IA n'est pas un simple compléteur de texte, mais un **agent logiciel autonome** doté d'une boucle d'action :
1. **Perception** : L'agent lit le système de fichiers, analyse les erreurs du compilateur TypeScript et consulte les métriques Git.
2. **Raisonnement** : Il décompose une tâche complexe en sous-objectifs indépendants.
3. **Action outillée (Tool Use / MCP)** : Il utilise des outils sécurisés pour modifier les fichiers, exécuter `npm run build` ou interroger une base de données locale.
4. **Auto-Correction** : Si un test unitaire échoue, l'agent inspecte la trace d'erreur et corrige son propre code de manière autonome jusqu'au succès.

## 4. Les Quatre Piliers du Développement Agentique en Entreprise

Pour transformer l'IA en un levier d'ingénierie industrielle, mettez en place ces quatre garde-fous :

### 4.1 La Spécification Avant la Génération (*Spec-Driven*)
Ne demandez jamais à un agent d'implémenter une fonctionnalité sans lui fournir au préalable les interfaces de données, les schémas Zod ou les contrats GraphQL. Les types délimitent le périmètre de jeu de l'agent.

### 4.2 Le Harnais de Tests Automatisés (TDD)
Écrivez d'abord le test d'intégration qui échoue (phase rouge). Donnez pour consigne à l'agent : « *Voici le test qui plante, modifie le code source pour le faire passer au vert sans régresser sur les autres tests.* » L'agent ne se base plus sur des "vibes", mais sur un verdict binaire indiscutable.

### 4.3 Les Outils et le Protocole MCP (*Model Context Protocol*)
Connectez l'agent à son environnement via le standard MCP : accès en lecture seule aux logs de production, consultation de la documentation officielle, exécution de linters. L'agent ne devine plus : il vérifie les faits.

### 4.4 La Revue de Code Humaine Critique
Chaque modification proposée par un agent doit faire l'objet d'un examen attentif du diff Git avant tout commit. L'ingénieur reste légalement et techniquement responsable du code livré.
