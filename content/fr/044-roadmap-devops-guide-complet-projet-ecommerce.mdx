# Roadmap DevOps : Guide Complet et Projet E-Commerce Réel

« *Par quoi commencer pour devenir ingénieur DevOps en partant de zéro ? Dois-je apprendre Kubernetes avant Linux ? Terraform avant Docker ?* »

Le monde du DevOps est un raz-de-marée d'outils, de logos et d'acronymes. Beaucoup de développeurs et d'administrateurs système se noient dans cette profusion technologique en essayant de tout apprendre en même temps, sans fil conducteur logique.

Le DevOps n'est pas une simple collection d'outils : c'est une culture d'ingénierie qui aligne le développement (*Dev*) et les opérations système (*Ops*) pour livrer des logiciels fiables à haute fréquence.

Dans ce guide de référence, nous détaillons la **feuille de route DevOps étape par étape**, définissons le rôle exact de chaque technologie fondamentale, puis illustrons leur synergie parfaite à travers un **cas concret de production : le déploiement d'une plateforme E-commerce multi-services**.

## 1. Rôle de Chaque Technologie et Étape de la Roadmap

### 1.1 DevOps Basics (Culture et Méthodologie)
Le point de départ indispensable. Le DevOps vise à abattre les silos organisationnels entre les développeurs qui créent les fonctionnalités et les exploitants système qui garantissent la stabilité. L'objectif est d'accélérer le cycle de vie du développement logiciel (*SDLC*) grâce à l'automatisation et à la boucle de rétroaction continue.

### 1.2 Linux Basics (Le Système d'Exploitation du Cloud)
Plus de 90% des serveurs cloud et 100% des conteneurs s'exécutent sous Linux (Debian, Ubuntu, Alpine, RHEL). Maîtrisez les commandes bash, la gestion des permissions (`chmod`, `chown`), la manipulation des processus (`systemd`, `ps`, `kill`), le réseau (`netstat`, `iptables`, `curl`) et l'édition de fichiers en ligne de commande.

### 1.3 Git Basics (Gestion de Version et Collaboration)
Le code source, les fichiers de configuration et les définitions d'infrastructure doivent être historisés. La maîtrise de Git (branches, rebase, merges, tags sémantiques, résolution de conflits) est le préalable absolu à tout pipeline automatisé.

### 1.4 Cloud Basics (AWS, Azure, GCP)
Les géants du Cloud fournissent des ressources informatiques à la demande via Internet :
- **Compute** : Machines virtuelles (AWS EC2, Azure VMs).
- **Storage** : Stockage d'objets immuable et hautement disponible (AWS S3, Azure Blob).
- **Managed Databases** : Bases de données sans maintenance de serveur (AWS RDS, Cloud SQL).
- **Networking** : Réseaux privés virtuels étanches (VPC, sous-réseaux, tables de routage).

### 1.5 Terraform (Infrastructure as Code - IaC)
Fini les clics manuels dans les consoles web AWS ou Azure. Avec Terraform, vous déclarez toute votre infrastructure (serveurs, réseaux, clusters) dans des fichiers de code déclaratifs (`.tf`). Vous pouvez prévisualiser les changements avec `terraform plan` et les appliquer de manière reproductible et automatisée avec `terraform apply`.

### 1.6 Ansible (Automatisation et Gestion de Configuration)
Outil d'automatisation sans agent (*agentless*) opérant via une simple liaison SSH sécurisée. Grâce à des playbooks rédigés en YAML, Ansible configure des centaines de machines en parallèle : mise à jour de paquets, durcissement des règles de pare-feu, déploiement de clés SSH et installation d'outils système de façon totalement idempotente.

### 1.7 Docker (Conteneurisation)
Docker encapsule une application et l'ensemble de ses dépendances (runtime, bibliothèques, configurations) dans une image isolée et légère. Il élimine définitivement le syndrome du « *ça marche sur mon poste mais pas sur le serveur* ».

### 1.8 Kubernetes (Orchestration de Conteneurs)
Si Docker crée les conteneurs, Kubernetes (K8s) les pilote à grande échelle. Il gère l'auto-réparation (*self-healing* si un conteneur plante), la répartition de charge (*load balancing*), les montées en charge automatiques (*Horizontal Pod Autoscaling*) et les déploiements progressifs sans interruption (*rolling updates*).

### 1.9 Python Basics (Le Couteau Suisse de l'Automatisation)
Langage de prédilection des ingénieurs DevOps pour concevoir des scripts d'administration système, interagir avec les API des fournisseurs de cloud via le SDK `boto3`, analyser des logs massifs ou écrire des bots de monitoring.

### 1.10 Jenkins & Cloud Pipelines (Moteurs CI/CD)
Les serveurs d'automatisation (Jenkins en open-source, ou AWS CodePipeline / Azure Pipelines) exécutent automatiquement les étapes de compilation, de test, de construction d'images Docker et de livraison continue dès l'arrivée d'un nouveau commit.

### 1.11 Hands-on Labs & Préparation aux Entretiens
La théorie ne suffit pas : construire des projets concrets de bout en bout, documenter son architecture sur GitHub et être capable d'expliquer ses arbitrages techniques (pourquoi K8s plutôt qu'un simple VPS, comment gérer les secrets) fait la différence lors des entretiens d'embauche.

## 2. Cas Concret : Déploiement d'une Application E-Commerce Multi-Services

Pour comprendre l'articulation réelle de ces technologies, examinons le déploiement d'une plateforme e-commerce composée de trois microservices : Service Catalogue, Service Panier et Service Paiement.

│                                  │                                     │
│                                  ▼                                     │
│ 2. ANSIBLE & LINUX                                                     │
│   Configure les serveurs Bastion SSH et durcit les règles de sécurité │
│                                  │                                     │
│                                  ▼                                     │
│ 3. GIT & DEV COLLABORATION                                             │
│   Les devs écrivent les microservices et ouvrent une Pull Request      │
│                                  │                                     │
│                                  ▼                                     │

### Étape 1 : Provisionnement de l'Infrastructure (Terraform & Cloud)
Grâce à Terraform, vous écrivez un manifeste déclaratif décrivant l'environnement complet sur AWS : un réseau virtuel (VPC) avec sous-réseaux privés et publics, une base PostgreSQL managée sur AWS RDS et un cluster Kubernetes managé (AWS EKS).
Une seule commande `terraform apply` crée toute cette infrastructure en 15 minutes, de façon 100% reproductible.

```hcl
# main.tf : Provisionnement d'un cluster Kubernetes managé (EKS)
module "eks" {
  source          = "terraform-aws-modules/eks/aws"
  version         = "~> 20.0"
  cluster_name    = "ecommerce-production-cluster"
  cluster_version = "1.30"

  vpc_id     = module.vpc.vpc_id
  subnet_ids = module.vpc.private_subnets

  eks_managed_node_groups = {
    general_nodes = {
      instance_types = ["t3.medium"]
      min_size       = 2
      max_size       = 6
      desired_size   = 3
    }
  }
}
```

### Étape 2 : Configuration des Machines (Linux & Ansible)
Si une machine virtuelle Linux sert de serveur de rebond (*Bastion*) pour accéder de manière sécurisée aux bases de données privées, un playbook Ansible applique automatiquement les politiques de sécurité : désactivation de l'authentification par mot de passe SSH, installation du pare-feu `fail2ban` et configuration des utilisateurs.

### Étape 3 : Développement et Versionnage (Git)
Les développeurs travaillent sur les microservices, testent localement leurs fonctionnalités et poussent leurs modifications sur une branche dédiée via Git. Une *Pull Request* est créée pour revue de code.

### Étape 4 : Pipeline CI/CD (Jenkins / AWS Pipelines)
Dès la fusion du code sur la branche `main`, un webhook déclenche immédiatement le pipeline d'intégration continue :
- Lancement des tests unitaires et d'intégration écrits en Python ou TypeScript.
- Analyse statique de sécurité pour vérifier l'absence de failles ou de secrets injectés.

### Étape 5 : Conteneurisation (Docker)
Si les tests sont validés avec succès :
- Le pipeline compile l'application et construit l'image Docker de production.
- L'image reçoit un tag sémantique immuable (ex: `ecommerce-api:v1.2.0-abc1234`).
- L'image est poussée vers un registre d'images sécurisé (AWS ECR ou Docker Hub).

### Étape 6 : Orchestration et Déploiement (Kubernetes)
Le pipeline applique les manifestes Kubernetes sur le cluster de production :
- **Rolling Update** : Kubernetes télécharge la nouvelle image Docker et remplace les anciens conteneurs un à un. Les clients du site e-commerce ne subissent aucune interruption de service.
- **Auto-scaling** : Lors d'un pic de trafic soudain (ex: Black Friday), le *Horizontal Pod Autoscaler* (HPA) détecte l'augmentation de la consommation CPU et démarre instantanément de nouveaux conteneurs pour absorber la charge.

## 3. L'Analogie du Monde Réel : L'Orchestre Philharmonique

> **L'Analogie de l'Orchestre Philharmonique :** 
> - **L'Infrastructure Cloud et Terraform** représentent la **salle de concert et la scène** : elles créent l'espace physique acoustique où tout va se jouer.
> - **Linux et Ansible** sont les **techniciens de scène et accordeurs** qui préparent chaque siège et s'assurent que chaque instrument est parfaitement calibré.
> - **Git** est la **partition musicale écrite** : chaque note y est annotée et partagée entre tous les musiciens.
> - **Docker** est l'**étui hermétique de chaque instrument** qui protège le violon contre l'humidité pour qu'il sonne exactement de la même manière dans n'importe quel pays.
> - **Le Pipeline CI/CD** est la **répétition générale** : si une seule note sonne faux, on recommence avant que le public n'arrive.
> - **Kubernetes** est le **Chef d'Orchestre** : il donne le tempo en direct, fait entrer les cuivres plus fort quand la charge monte, et remplace discrètement un musicien s'il fait un malaise sans que le public ne s'en aperçoive.

## ❓ FAQ Schema : Questions Fréquentes sur la Roadmap DevOps

### Dois-je apprendre le développement logiciel avant de faire du DevOps ?
Il n'est pas nécessaire d'être un développeur fullstack chevronné, mais maîtriser les bases du code (structures de données, programmation orientée objet, manipulation d'API REST) en Python ou en JavaScript/TypeScript est indispensable pour automatiser et comprendre les contraintes des équipes de développement.

### Pourquoi utiliser Terraform plutôt qu'Ansible pour l'infrastructure ?
**Terraform** excelle dans l'**orchestration d'infrastructure immuable** (créer et détruire des réseaux, serveurs, bases de données cloud). **Ansible** excelle dans la **gestion de configuration logicielle** sur des serveurs existants (installer des logiciels, éditer des fichiers de configuration, gérer des utilisateurs). Ils sont complémentaires et s'utilisent souvent ensemble.

### Combien de temps faut-il pour devenir ingénieur DevOps ?
Pour un profil ayant déjà des bases en développement ou en administration système, comptez entre **6 et 12 mois** de pratique intensive axée sur des projets concrets (labs, conteneurisation d'applications réelles, mise en place de pipelines CI/CD et déploiement sur le cloud).
