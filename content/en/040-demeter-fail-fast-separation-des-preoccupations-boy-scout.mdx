# Law of Demeter, Fail Fast, Separation of Concerns, and the Boy Scout Rule: Writing Robust Code

Writing code that works during a demo is simple. But engineering a software system that remains maintainable three years later without turning into a fragile nightmare requires continuous discipline.

Beyond high-level paradigms like SOLID or DRY, daily software health depends on four fundamental architectural and code hygiene rules:
1. **The Law of Demeter (LoD)**: Minimizing object coupling.
2. **The Fail Fast Principle**: Catching invalid states immediately at the boundary.
3. **Separation of Concerns (SoC)**: Isolating independent system layers.
4. **The Boy Scout Rule**: Continuously reducing technical debt.

Here is how to master these four principles with **real-world analogies** and **TypeScript code**.

## 1. 🤫 The Law of Demeter (LoD) — Principle of Least Knowledge

> **Rule:** An object should only invoke methods on its immediate collaborators and never reach through dependencies into internal structures.

### The Real-World Analogy
> **The Newsagent Analogy:** When buying a newspaper at a corner kiosk, you do not hand your open wallet to the cashier saying: *"Go ahead, open my wallet, search for the coin pocket, take 3 dollars, and zip it shut"*. Instead, you ask for the price, extract the 3 dollars yourself, and hand over the money. The cashier has no business knowing the internal layout of your wallet.

### TypeScript Example

#### ❌ The "Train Wreck" Anti-Pattern
A brittle chain of deep invocations:

```typescript
// ❌ DANGEROUS COUPLING (Train Wreck)
function printEmployeeZipCode(employee: Employee) {
  // If 'department' is renamed or made optional, this code throws a runtime error!
  const zip = employee.getCompany().getDepartment().getManager().getAddress().getZipCode();
  console.log(zip);
}
```

#### ✅ The Demeter-Compliant Solution
Delegate the query through the immediate collaborator:

```typescript
// ✅ Clean encapsulation
function printEmployeeZipCode(employee: Employee) {
  const zip = employee.getManagerZipCode();
  console.log(zip);
}
```

## 2. ⚡ The Fail Fast Principle

> **Rule:** Validate inputs immediately upon entering a function. If any condition is violated, throw an error or return immediately rather than letting bad state propagate down the call stack.

### The Real-World Analogy
> **The Nightclub Bouncer Analogy:** A bouncer checks your ID and attire right at the entrance door. He does not let you inside the venue only to tackle you two hours later on the dance floor while you are ordering a drink. Access is denied immediately at the perimeter.

### TypeScript Example

#### ❌ Before: The Deep Pyramid of Doom

```typescript
// ❌ NESTED PYRAMID HARD TO READ AND AUDIT
function processTransfer(account: Account | null, amount: number) {
  if (account !== null) {
    if (account.isActive) {
      if (amount > 0) {
        if (account.balance >= amount) {
          account.balance -= amount;
          return { success: true };
        } else {
          throw new Error("Insufficient funds");
        }
      } else {
        throw new Error("Invalid amount");
      }
    } else {
      throw new Error("Inactive account");
    }
  } else {
    throw new Error("Nonexistent account");
  }
}
```

#### ✅ After: Guard Clauses (Fail Fast)

```typescript
// ✅ FAIL FAST: IMMEDIATE EXIT ON ERROR
function processTransfer(account: Account | null, amount: number) {
  if (!account) throw new Error("Nonexistent account");
  if (!account.isActive) throw new Error("Inactive account");
  if (amount <= 0) throw new Error("Invalid amount");
  if (account.balance < amount) throw new Error("Insufficient funds");

  // Happy path remains completely unindented:
  account.balance -= amount;
  return { success: true };
}
```

## 3. 🧩 SoC — Separation of Concerns

> **Rule:** Partition the program into distinct sections, where each section addresses a separate concern.

### The Real-World Analogy
> **The Restaurant Brigade Analogy:** In a professional kitchen, the head chef cooks, the sommelier pairs wines, the server delivers plates, and the cashier processes credit cards. If the chef had to leave the stove to run into the dining room and make change for customers, the food would burn and the financial ledger would be incorrect.

### TypeScript Example (Modern Web UI)

#### ❌ Before: The All-In-One Spaghetti Component

```typescript
// ❌ MIXING NETWORK, DOMAIN LOGIC, AND RENDERING
export function BadInvoiceWidget({ invoiceId }: { invoiceId: string }) {
  const [data, setData] = useState<any>(null);

  useEffect(() => {
    fetch(`/api/invoices/${invoiceId}`)
      .then(res => res.json())
      .then(invoice => {
        const vat = invoice.rawAmount * 0.20;
        const total = invoice.rawAmount + vat;
        setData({ ...invoice, total });
      });
  }, [invoiceId]);

  return <div>Invoice: {data?.total} USD</div>;
}
```

#### ✅ After: Clean Separation of Concerns

```typescript
// 1. Pure Domain Logic (Testable independently from UI)
export function computeInvoiceTotal(rawAmount: number): number {
  const VAT_RATE = 0.20;
  return rawAmount * (1 + VAT_RATE);
}

// 2. Data Hook (Isolated network concern)
export function useInvoice(invoiceId: string) {
  return useQuery({
    queryKey: ["invoice", invoiceId],
    queryFn: () => fetchInvoiceById(invoiceId),
    select: (data) => ({
      ...data,
      total: computeInvoiceTotal(data.rawAmount),
    }),
  });
}

// 3. Presentation Component (Exclusive UI concern)
export function CleanInvoiceWidget({ invoiceId }: { invoiceId: string }) {
  const { data, isLoading } = useInvoice(invoiceId);

  if (isLoading) return <Spinner />;
  return <div>Invoice: {data?.total} USD</div>;
}
```

## 4. 🏕️ The Boy Scout Rule

> **Rule:** "Always leave the campground cleaner than you found it."

### The Real-World Analogy
> **The Hiking Trail Analogy:** When scouts hike through a forest, they do not merely carry out their own trash. If they spot an abandoned soda can or plastic bag discarded by a previous traveler, they pick it up and dispose of it. Because of this small, repeated habit, the forest grows cleaner over time.

### In Your Daily Codebase
You never need to request a two-week "refactoring pause" that management will inevitably reject.

Every time you touch a file to add a feature or fix a bug:
1. Rename that obscure `tmp3` variable to an explicit name `activeSessionToken`.
2. Delete that 10-line block of commented-out dead code from 2023.
3. Replace an unsafe `any` with an explicit TypeScript type guard.
4. Extract a magic number into a named constant (`86400000` $\rightarrow$ `ONE_DAY_IN_MS`).

> **The Compound Effect:** If five engineers apply the Boy Scout Rule daily across two files, your codebase receives **2,000 small improvements every year**. Technical debt stops accumulating—it steadily shrinks.
