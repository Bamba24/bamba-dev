# Complete NestJS Guide: Modular Architecture, Decorators, and Dependency Injection

When it comes to building complex server-side applications with Node.js, **NestJS** has established itself as the premier TypeScript framework. Directly inspired by Angular's architecture and design patterns, NestJS provides a strict, strongly typed, and highly maintainable modular structure out of the box.

In this article, we will explore the core pillars of NestJS: **Modules**, **Controllers**, **Services (Providers)**, and **Dependency Injection**, followed by an overview of NestJS's execution lifecycle.

---

## 1. Modular Architecture

In NestJS, everything is organized into **Modules**. A module is a class annotated with the `@Module()` decorator that provides the metadata Nest uses to organize application structure and dependencies.

```typescript
// user.module.ts
import { Module } from '@nestjs/common';
import { UserController } from './user.controller';
import { UserService } from './user.service';

@Module({
  controllers: [UserController],
  providers: [UserService],
  exports: [UserService], // Exporting service for consumption by other modules
})
export class UserModule {}
```

Each main feature domain of your application (Users, Auth, Payments) resides in its own isolated module, all imported into the root `AppModule`.

## 2. Controllers

Controllers are responsible for handling incoming HTTP requests and returning structured responses to the client. They utilize intuitive decorators to map routes (`@Get()`, `@Post()`, `@Put()`, `@Delete()`).

```typescript
// user.controller.ts
import { Controller, Get, Post, Body, Param, ParseIntPipe } from '@nestjs/common';
import { UserService } from './user.service';
import { CreateUserDto } from './dto/create-user.dto';

@Controller('users')
export class UserController {
  constructor(private readonly userService: UserService) {}

  @Get()
  async findAll() {
    return this.userService.findAll();
  }

  @Get(':id')
  async findOne(@Param('id', ParseIntPipe) id: number) {
    return this.userService.findOne(id);
  }

  @Post()
  async create(@Body() createUserDto: CreateUserDto) {
    return this.userService.create(createUserDto);
  }
}
```

<Note>
Notice the use of `ParseIntPipe`: Pipes in NestJS automatically validate and transform incoming request parameters before they reach controller route handlers.
</Note>

## 3. Services and Dependency Injection (DI)

Controllers should remain lean and only handle HTTP protocol concerns. All business logic, database queries, and rule evaluations belong in **Injectable Services**:

```typescript
// user.service.ts
import { Injectable, NotFoundException } from '@nestjs/common';

export interface User {
  id: number;
  name: string;
  email: string;
}

@Injectable()
export class UserService {
  private users: User[] = [];

  async findAll(): Promise<User[]> {
    return this.users;
  }

  async findOne(id: number): Promise<User> {
    const user = this.users.find((u) => u.id === id);
    if (!user) {
      throw new NotFoundException(`User with ID ${id} not found`);
    }
    return user;
  }

  async create(userDto: Omit<User, 'id'>): Promise<User> {
    const newUser = { id: Date.now(), ...userDto };
    this.users.push(newUser);
    return newUser;
  }
}
```

NestJS automatically manages service instantiation and lifecycle via its built-in **Inversion of Control (IoC) Container**.

## 4. NestJS Request Execution Pipeline

Here is the exact request handling lifecycle inside NestJS:

| Stage | NestJS Feature | Purpose |
| :--- | :--- | :--- |
| 1 | **Middlewares** | Intercepts HTTP requests before route handler matching (e.g., logging, CORS). |
| 2 | **Guards** | Handles authentication and authorization (e.g., JWT Auth Guard). |
| 3 | **Interceptors** | Transforms request/response payloads or decorates execution (e.g., caching, response mapping). |
| 4 | **Pipes** | Validates and converts request payloads/parameters against DTO schemas. |
| 5 | **Controller** | Executes the matched handler and calls underlying services. |
| 6 | **Exception Filters** | Catches unhandled exceptions and formats clean HTTP error responses. |
