## 1. The Global AWS Physical Infrastructure

AWS physical infrastructure is structured across three concentric geographical layers connected by private, high-bandwidth optical networks:

1. **Regions**: Physically separated geographic clusters across the globe (e.g., `eu-west-3` in Paris, `us-east-1` in North Virginia). Each region operates independently to maintain strict data residency compliance.
2. **Availability Zones (AZs)**: Each region consists of at least three isolated, discrete physical datacenters separated by dozens of kilometers to survive natural disasters while linked via ultra-low latency optical transit (less than 2 ms).
3. **Edge Locations**: Hundreds of points of presence strategically distributed in major metropolitan centers worldwide to cache static content close to users via the **Amazon CloudFront** CDN.

## 2. Core Security: AWS IAM (Identity and Access Management)

Cloud security on AWS is governed by a singular doctrine: **the principle of least privilege**.

```txt
┌────────────────────────────────────────────────────────────────────────┐
│                        IAM SECURITY HIERARCHY                          │
├────────────────────────────────────────────────────────────────────────┤
│ ROOT ACCOUNT (Locked with hardware MFA, NEVER used for routine work)   │
│       │                                                                │
│       ├──► IAM Users (Human identities for engineers)                  │
│       ├──► IAM Groups (Role bundles: Developers, Admins, SecOps)       │
│       └──► IAM Roles (Ephemeral identities assumed by machines/lambda) │
│                 │                                                      │
│                 ▼                                                      │
│           IAM Policies (JSON contracts explicitly declaring Allow/Deny)│
└────────────────────────────────────────────────────────────────────────┘
```

### Golden IAM Rules
- **Lock Down the Root Account**: Activate multi-factor authentication (MFA) immediately upon account creation and store recovery keys offline.
- **Embrace IAM Roles**: Never embed static long-lived API keys (`AWS_ACCESS_KEY_ID`) inside virtual machines or containers. Attach an **IAM Role** to your EC2 instance: the AWS metadata service generates, rotates, and injects short-lived credentials automatically.
- **Declarative JSON Policy Enforcement**: Specify exact target actions and resources:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowS3InvoiceRead",
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::bambadev-invoices-bucket",
        "arn:aws:s3:::bambadev-invoices-bucket/*"
      ]
    }
  ]
}
```

## 3. Network Isolation: Amazon VPC (Virtual Private Cloud)

An **Amazon VPC** represents your private, isolated virtual datacenter carved out inside AWS.

- **Public Subnets**: Connected directly to the public internet through an **Internet Gateway (IGW)**. They host customer-facing Application Load Balancers.
- **Private Subnets**: Devoid of public IP addresses. Application workloads and container pods execute here. To retrieve OS security patches, they route outbound traffic through a **NAT Gateway** positioned in the public subnet.
- **Security Groups vs Network ACLs**:
  - *Security Group (Stateful)*: Operates as a virtual firewall at the network interface level (allowing inbound port 443 automatically permits corresponding outbound replies).
  - *Network ACL (Stateless)*: Evaluates network traffic packets at the subnet boundary, requiring explicit inbound and outbound rule pairing.

## 4. Compute and Storage Building Blocks

### 4.1 Compute: From Virtual Machines to Serverless
- **Amazon EC2 (Elastic Compute Cloud)**: Resizable virtual servers. Paired with *Auto Scaling Groups*, they expand and contract dynamically based on real-time CPU saturation.
- **AWS Lambda (Serverless)**: Runs code directly in response to events with zero server provisioning. Billed strictly in 100-millisecond compute increments.
- **Amazon ECS / EKS**: Enterprise container orchestration services for Docker and Kubernetes workloads, offering **AWS Fargate** to run containers without managing compute instances.

### 4.2 Storage: Objects, Blocks, and Files
- **Amazon S3 (Simple Storage Service)**: Resilient object store offering 99.999999999% (11 9s) of data durability. Ideal for static assets, backups, and media files.
- **Amazon EBS (Elastic Block Store)**: High-performance, low-latency block-level storage volumes attached directly to EC2 instances.

### 4.3 Databases: Managed Relational and NoSQL
- **Amazon RDS (Relational Database Service)**: Automated provisioning of PostgreSQL and MySQL engines featuring synchronous multi-AZ replication for automated disaster failover.
- **Amazon DynamoDB**: Fully managed NoSQL key-value database delivering predictable single-digit millisecond latency at any throughput scale.

## ❓ FAQ Schema: Frequently Asked Questions

### What is the difference between AWS Fargate and EC2 for running containers?
With **EC2**, you manage the underlying virtual machines yourself, including operating system patches and cluster scaling. With **AWS Fargate**, the server infrastructure is completely abstract: you specify the required CPU and memory footprint, and AWS provisions and runs the containers seamlessly.

### How do I prevent unexpected billing surprises on AWS?
Configure **AWS Budgets** to trigger proactive email alerts when actual or forecasted monthly spending reaches 80% of your threshold. Additionally, implement Amazon S3 Lifecycle Rules to transition older backups automatically to cold storage classes like Amazon Glacier.

### Why should application servers use a NAT Gateway instead of public IP addresses?
Assigning public IP addresses to backend instances exposes them directly to automated vulnerability port scans and brute force attacks from the internet. A **NAT Gateway** allows instances in private subnets to initiate outbound internet connections (for updates or third-party API calls) while completely forbidding unsolicited inbound connections.
